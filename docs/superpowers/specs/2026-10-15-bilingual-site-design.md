# SplitMate 全站中英切換設計

日期：2026-10-15

## 目的與成功條件

SplitMate 目前以繁體中文顯示主要操作介面。使用者希望把頁面右上角的「建立活動」連結改為中／英文切換按鈕，並讓切換影響整個網站，而非只影響首頁。首頁與空狀態中原有的建立活動入口保留。

成功時，使用者可從任何頁面切換繁體中文與英文，留在原頁面繼續操作；重新導覽或稍後再次造訪時，仍使用所選語言。未曾選擇語言者預設看到繁體中文。輸入與儲存的活動名稱、成員姓名、支出名稱不被翻譯或改寫。

## 範圍

- 翻譯網站公開的五類頁面：首頁、建立活動、活動明細、新增支出、分帳結果。
- 翻譯共用導覽、頁面標題、按鈕、提示、空狀態、支出刪除對話框、表單標籤／佔位文字／驗證錯誤，以及新增成員等前端動態文字。
- Django 管理介面沿用 Django 自帶的語言支援；本設計不另做管理介面的自訂翻譯或版面。
- 維持現有 URL、資料庫內容、金額單位 NT$ 和分帳計算。使用者輸入的資料原樣顯示並保留 HTML 跳脫。
- 不做機器翻譯、匯率轉換、按語言複製資料，亦不建立另一個網站或發佈服務。

## 介面與互動

右上角原本的「建立活動」位置改放單一切換按鈕。繁體中文介面顯示 `EN`，英文介面顯示 `中文`；輔助說明分別清楚指出即將切換至哪個語言。按鈕在手機版也可見、可用鍵盤操作，尺寸符合現有控制項標準。首頁主要的「建立新活動」按鈕和無活動時的建立入口保持原位。

切換採表單 POST，包含 CSRF 防護。成功後返回當前站內頁面，不遺失頁面路徑或查詢參數。選擇儲存於語言 cookie；不要求登入，並允許在任何頁面再次切回。若切換發生在尚未提交的建立／新增表單，返回的是同一路徑的 GET 頁面，尚未送出的輸入不承諾保留；切換控制應可理解為頁面導覽。

頁面根元素的 `lang` 與當前語言一致。英文版保留既有英文品牌標語；其餘使用者可見文字須為自然英文，而非混雜中文。數量相關文字使用可翻譯的複數形式，避免直接拼接「數字 + 中文單位」。

## 技術設計

採 Django 內建國際化機制，不維護兩套模板。設定支援 `zh-hant` 和 `en`，以 `zh-hant` 為預設；在中介層加入 `LocaleMiddleware`，使用 Django 的語言切換端點和安全的站內返回處理。模板使用 Django 翻譯標記，Python 表單、模型驗證和檢視使用可延後求值的翻譯字串或請求時翻譯。英文翻譯集中於版本控管的語言目錄及編譯後目錄；編譯步驟在本機 Windows 環境可重現，不依賴使用者預先全域安裝 GNU gettext。

目前分帳結果的狀態以中文字串判斷顏色與顯示，實作時需把穩定的狀態代碼與翻譯後的顯示標籤分開，避免切到英文後改變分帳邏輯或樣式。前端新增／刪除成員時的動態標籤由模板傳入當前語言字串，不在 JavaScript 內固定寫中文。翻譯與顯示層不修改 `Activity`、`Member`、`Expense` 的既有資料關係；預期不需資料庫遷移。

## 驗證與驗收

- 預設繁體中文；從首頁及各內頁切到英文後，標題、導覽、主要文字與表單均為英文，按鈕能切回中文。
- 切換後維持原路徑，並在後續導覽與重新造訪時保留選擇；返回目標不能導向外站。
- 建立活動、新增支出、刪除支出、檢視分帳結果在兩種語言下均可正常操作，驗證錯誤也使用所選語言。
- 成員數／支出數的單複數、刪除確認對話框，以及 JavaScript 新增成員標籤在英文版不殘留中文。
- 使用者既有資料不改變；桌面與手機版的語言按鈕可見、可操作且不破壞版面。
- 完整 Django 測試及代表性瀏覽器互動測試通過，並驗證本機頁面實際呈現。
